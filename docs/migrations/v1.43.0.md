# Upgrading to v1.43.0

`v1.43.0` replaces the hotfix engine with backports. A fix lands on the default branch through its
normal pull request first. `backport-run` then carries it onto the release line `release/vX.Y` as a
backport pull request, and merging that pull request cuts the patch through `release-line-run`.

The old engine cut the patch from an ephemeral branch and reconciled it forward. A fix written
against unreleased work could ship that work, or pass review against code that was never released.
A backport is reviewed and tested against the released code, and a fix that does not apply cleanly
opens nothing: the run prints the commands to write the release line's form of the fix by hand.

## Do I need to act?

**Only through `a-novel repo update`.** The `hotfix.yaml` caller and the `release/**` ruleset are
provisioned by the stack CLI, so a repository adopts the change when its config is next applied.
`hotfix-run` keeps working until then and is removed in a later release.

## The caller

`hotfix.yaml` gains a push trigger and a second job. The dispatch backports the fixes; the push of a
merged backport cuts the patch, serialised per line.

```yaml
on:
  workflow_dispatch:
    inputs:
      line: { required: true, type: string }
      fix_refs: { required: false, type: string, default: "" }
      severity: { required: false, type: choice, options: [sev2, sev1], default: sev2 }
      dry_run: { required: false, type: boolean, default: true }
  push:
    branches: ["release/**"]

jobs:
  backport:
    if: github.event_name == 'workflow_dispatch'
    permissions:
      contents: read
    uses: a-novel-kit/workflows/.github/workflows/backport-run.yaml@v1.43.0
    with:
      line: ${{ inputs.line }}
      fix_refs: ${{ inputs.fix_refs }}
      # severity, dry_run, client_id, project_id, mention and secrets as for hotfix-run
  cut:
    if: github.event_name == 'push'
    concurrency:
      group: release-line-${{ github.repository }}-${{ github.ref_name }}
      cancel-in-progress: false
    permissions:
      contents: read
      actions: read
    uses: a-novel-kit/workflows/.github/workflows/release-line-run.yaml@v1.43.0
    with:
      dry_run: false
      # client_id, project_id, mention and secrets as above
```

`fix_refs` replaces `fix_ref`: space-separated commit SHAs already on the default branch, oldest
first. A range is no longer accepted, since each fix becomes its own pull request.

## The release line

The [Agent] App pushes the bump commit to `release/vX.Y` together with the patch tags, so its
installation needs a bypass of the release-line ruleset as well as of the tag ruleset. The `release`
environment still gates the cut.

## The watchdog

`watchdog` reports a pull request into `release/*` that stays open longer than
`stale_backport_hours` (default 24). Callers need no change.
