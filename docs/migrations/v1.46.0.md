# Upgrading to v1.46.0

`v1.46.0` makes `generic-actions/approve-playwright` remove the `allow-screenshot-change` label when
a push reaches the PR. The label approves one exact head, so it went stale on every push, and a
reviewer had to remove it and add it again to approve the new head. Now they only add it.

`generic-actions/approve-translations` now does the same for `allow-incomplete-translations` and
`allow-translation-drift` on every push, not only on one that changes a catalog: each label approves
the head it was added on. Its `catalogs` input is gone; drop it if a caller passes it.

## Do I need to act?

**Only in platforms that call `approve-playwright`.** Grant its job `pull-requests: write`, which
removing a label needs:

```yaml
approval:
  permissions:
    contents: read
    actions: write
    statuses: write
    pull-requests: write
```

Without it, a push to a PR that still carries the label fails the approval job. Approval itself is
unchanged: the receipt for the new head still records no approval until the label is added again.

## What reviewers see

- After a push, the screenshot label is gone and the approval run's summary says why. The
  translation labels go too, and the translation check reruns without them.
- Removing them uses the job's `GITHUB_TOKEN`, which starts no new workflow run.
