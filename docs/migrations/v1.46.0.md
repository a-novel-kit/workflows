# Upgrading to v1.46.0

`v1.46.0` binds the `append-only-override` label to the head it was added on, like the screenshot and
translation labels since `v1.45.3`. A push's payload still carries the label, so the label used to
waive the check for any later change under the frozen path, reviewed or not.

`generic-actions/check-append-only` now checks a push without the label. Given a token, it also removes
the label, so a reviewer can add it again once the new head is reviewed. Adding a label runs the
caller's workflow again only if it triggers on `labeled`.

The guide for the previous release shipped as `v1.46.0.md` by mistake; it is now
[`v1.45.3.md`](./v1.45.3.md), the release that carried it.

## Do I need to act?

**In every repository that calls `check-append-only`.** Without a token, a push ignores the label but
leaves it on the PR, and a reviewer has to remove it and add it again. Pass the job's token, and grant
the job `pull-requests: write`:

```yaml
check-migration-snapshots:
  permissions:
    contents: read
    pull-requests: write
  steps:
    - uses: a-novel-kit/workflows/generic-actions/check-append-only@v1.46.0
      with:
        path: internal/models/migrations/testdata/schema
        base: ${{ github.event.pull_request.base.sha }}
        github_token: ${{ github.token }}
```

Give each `check-append-only` step the token; the second one in a job finds the label already gone.
Keep `labeled` and `unlabeled` in the workflow's `pull_request` types, so adding the label re-runs the
check.
