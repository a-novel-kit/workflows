# Upgrading to v1.64.0

`node-actions/test-playwright` compares a Vitest browser project's screenshots against Drive
references, with the same approval, evidence and maintenance as Playwright journeys.

## Do I need to act?

**No** for Playwright callers. `runner` defaults to `playwright`, and their comparisons behave as
before. **Recommended** for a Vitest browser project that should catch visual changes in its own pull
requests, such as uikit's Storybook stories.

## Compare a Vitest browser project against Drive

Set up Drive first with the [adoption guide](./v1.33.0.md): identities, folders, repository variables,
`visual-tests.yaml` and the `allow-screenshot-change` label. Its conventions hold: the job ID stays
`test-browser`, and retries stay at zero.

Pass `runner: vitest`, and name the Vitest script as `test_action`:

```yaml
- uses: a-novel-kit/workflows/node-actions/test-playwright@v1.64.0
  with:
    github_token: ${{ secrets.GITHUB_TOKEN }}
    component_test_action: test:browser
    test_action: test:storybook
    runner: vitest
    drive_ci_provider: ${{ vars.VISUAL_CI_PROVIDER }}
    # …and the other Drive inputs from the adoption guide.
```

The runner appends `--update`, its reporter and `--attachmentsDir=test-results` to that script, so the
script must end in a `vitest run` command. The actual and diff images then join the Drive evidence.

Store each screenshot in the directory the runner provides:

```ts
browser: {
  expect: {
    toMatchScreenshot: {
      resolveScreenshotPath: ({ arg, ext }) => resolve(process.env.PLAYWRIGHT_SNAPSHOT_DIR ?? "", `${arg}${ext}`),
    },
  },
},
```

Declare every screenshot with a `visual-snapshot` annotation. Vitest reports nothing about a passing
`toMatchScreenshot`, so the annotations are the inventory, and the runner fails a run that writes a
screenshot no annotation declares. A Storybook project compares every story from one setup file:

```ts
import { afterEach, beforeEach, expect } from "vitest";
import type { TestContext } from "vitest";
import { page } from "vitest/browser";

// Vitest resolves a flat name of word characters and single hyphens, so the name uses no others.
const screenshot = ({ task }: TestContext) => `${task.file.name}-${task.name}`.replace(/\W+/g, "-") + ".png";

// Vitest accepts annotations only while the test runs, so the screenshot is declared before it.
beforeEach(async (context) => {
  await context.annotate(screenshot(context), "visual-snapshot");
});

afterEach(async (context) => {
  await document.fonts.ready;
  await expect(page).toMatchScreenshot(screenshot(context));
});
```

Vitest refuses an annotation once a test has finished or a soft assertion has failed it, so declare a
screenshot in `beforeEach` or before the first assertion. It also resolves only the file name of a
screenshot, keeping letters, digits, `_` and single hyphens. A name with a directory, an inner dot or a
double hyphen, such as a Storybook story ID, no longer matches its annotation.

Capture `page`, not a story's container. Modal dialogs and popovers render in the top layer, outside
every container, and a container capture misses them. Load the setup file only when
`PLAYWRIGHT_SNAPSHOT_DIR` is set, so the suite still runs without Drive:

```ts
setupFiles: process.env.PLAYWRIGHT_SNAPSHOT_DIR ? ["./.storybook/vitest.screenshot.ts"] : [],
```

Verify with the adoption guide's checks: a clean comparison, an unapproved and an approved pixel
change, and a functional failure that the label cannot waive.
