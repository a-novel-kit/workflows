# Upgrading to v1.82.0

`v1.82.0` retires Sentry. It removes `publish-actions/sentry-release` and the reusable
`sentry-intake-run.yaml`, and the base Renovate preset drops the `custom.sentry-cli` datasource. A
fault reaches the board when a person files it by hand from its Discord alert.

## Do I need to act?

**Only in a repository that still calls either one.** Delete the step and the caller before moving the
pins to `v1.82.0`, or in the same change. To list them:

```bash
grep -rn -E 'sentry-release@|sentry-intake-run\.yaml@' .github/workflows
```

A stale reference fails at this tag:

- **`sentry-release` in `release.yaml`.** The `cut` job fails before its first step, since the action
  no longer exists at this tag. Delete the step with its `custom.sentry-cli` annotation. The
  `id: release` that [v1.79.0](./v1.79.0.md) gave `release-core` can go too, unless another step
  reads it.
- **`sentry-intake.yaml`.** A workflow that references a missing reusable workflow fails to start.
  Delete the file.

## Drop the hotfix's Sentry token

`release-line-run` still accepts `sentry_auth_token` and ignores it, so a `hotfix.yaml` that passes it
keeps working. Delete the line and its comment from the `cut` job's `secrets:` block. The next planned
major removes the secret.

## Notes

Earlier tags keep the action and the workflow, so a release line that pins one needs nothing.
