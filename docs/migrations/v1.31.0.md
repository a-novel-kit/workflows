# Upgrading to v1.31.0

Renovate policy is published as JSON presets matching the CLI repository classes.

## Do I need to act?

Recommended. Existing callers retain their common policy. Adopt a class preset to make
the repository's configuration explicit and remove repeated rules.

1. Update every workflows action reference to `v1.31.0`.
2. Extend `github>a-novel-kit/workflows//renovate/<class>#v1.31.0` from `renovate.json`.
   Choose `service`, `platform`, `library`, `infra`, `workflows` or `meta`.
3. Set `repository_config: "true"` on the Renovate action in the same change.
4. Remove local rules and custom managers supplied by the class preset. Keep architecture,
   registry URLs, compatibility exceptions and repository-specific generation paths.
5. Preserve the action's `allowed_commands` override where required. The presets do not grant
   command permissions.

The service preset includes the database preset. Remove duplicate pgBackRest/apko/APK
managers when adopting it; retain the APK registry and architecture rule. Existing Debian
services can adopt the service preset while retaining their Debian registry rules.

Verify the resolved configuration and a Renovate extraction pass before merging. Preset
references and action references are updated together by the workflows dependency group.
See [Repository-class Renovate configuration](../renovate-presets.md) for the class mapping
and runner configuration.
