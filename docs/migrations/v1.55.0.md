# Upgrading to v1.55.0

`v1.55.0` stops the Node actions from minting a GitHub App token. `setup-node` minted the
Dependencies App's token only to check out the repository, and then dropped it: package installs
authenticate with the workflow token, and every repository and package is public. Each pull request
still ran with the App's private key, which any workflow on its branch can read.

`setup-node`, `lint-node`, `test-node`, `build-node`, `lint-translations`, `test-playwright`,
`publish-storybook` and `publish-actions/npm` no longer take `app_private_key` or `client_id`.
`setup-node` checks out with its `github_token`; its `token` output now returns that token, and its
`app_login` output is gone. `audit` still takes the App key, since it commits its fixes as the bot.

## Do I need to act?

**Drop `app_private_key` and `client_id` from those actions' `with:` blocks.** A caller that keeps
them still works, with an "Unexpected input" warning, but it keeps naming the secret, which keeps the
repository able to read it.

```diff
       - uses: a-novel-kit/workflows/node-actions/lint-node@v1.55.0
         with:
           github_token: ${{ secrets.GITHUB_TOKEN }}
-          app_private_key: ${{ secrets.DEPENDENCY_BOT_PRIVATE_KEY }}
-          client_id: ${{ vars.DEPENDENCY_BOT_CLIENT_ID }}
```

A later checkout that read `setup-node`'s `token` output keeps working: it now receives the workflow
token, which can read the repository and its LFS objects.
