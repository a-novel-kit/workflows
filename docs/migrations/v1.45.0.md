# Upgrading to v1.45.0

`v1.45.0` removes the reconcile hotfix path that v1.43.0 replaced with backports:
`.github/workflows/hotfix-run.yaml` and `generic-actions/hotfix-reconcile`. Every governed
repository's `hotfix.yaml` already calls `backport-run` and `release-line-run`.

Removing them is a small breaking change, since nothing calls them, so it ships as a minor.

## Do I need to act?

**Only if a workflow still calls `hotfix-run.yaml` or `hotfix-reconcile`.** None did across
`a-novel` and `a-novel-kit` when this release was cut. A `hotfix.yaml` that does is a stale copy:
reprovision it with `a-novel repo update`. Earlier tags still contain the old path, so such a
caller keeps working until it is re-pinned.

## Other changes

- `publish-actions/release-core-hotfix` drops its `branch` input. It now cuts the release line named
  by `ref` (`release/vX.Y`) and always pushes the bump commit back to it with the tags. Its only
  caller, `release-line-run`, already passes the line as `ref`.
- `generic-actions/derive-status` no longer treats a `hotfix-reconcile` Task as Done on merge.
  Every merged pull request moves the Tasks it closes to Awaiting release.
