# Upgrading to v1.67.2

`publish-actions/npm` attests the tarballs it publishes. It packs each public workspace package,
signs the tarballs through GitHub's attestation service, and publishes those exact files. The
attestation records the run's repository, workflow and ref, so a consumer can tell a version a release
tag published from one any other run published.

## Do I need to act?

**Yes**, in every job that calls `publish-actions/npm`. Grant the two permissions the attestation
needs beside `packages: write`, or the job fails before it publishes anything:

```yaml
permissions:
  contents: read
  packages: write
  attestations: write
  id-token: write
```

No secret is required: GitHub exchanges the job's OIDC identity for a short-lived signing certificate.

## Failure behavior

The action publishes nothing until every tarball is attested. When the attestation service fails,
re-run the job. A re-run skips each version the registry already holds.

## Verify a published version

Download the tarball the lockfile names, then verify it against the release tag that published it:

```bash
gh attestation verify service-authentication-rest-2.15.0.tgz \
  --repo a-novel/service-authentication \
  --signer-workflow a-novel/service-authentication/.github/workflows/release.yaml \
  --source-ref refs/tags/v2.15.0
```
