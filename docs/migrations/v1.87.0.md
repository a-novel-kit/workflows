# Upgrading to v1.87.0

The governance gates run from one reusable `gates-run.yaml`, the Dependabot path from
`dependabot-run.yaml`, board ids and privileged labels default inside the actions, and the
`go-tools` preset matches tool modfiles in any directory. The lint actions check out and pin their
scanners themselves, new actions replace the services' copied build, Compose and Pages steps, and
Node lanes on a pull request test the merge commit.

## Do I need to act?

**Recommended.** Nothing breaks: every caller of the previous release keeps working. Each change
below deletes lines from a repository's governance copies. Make them once the repository's pins name
this release or a later one, after Renovate's bump has merged. A deprecated path logs a warning that
names its successor, and the daily CI digest collects them.

Three changes act on their own:

- The five lint actions check the repository out again inside a job that already did, and that
  checkout removes untracked files earlier steps left in the workspace. No caller depends on such
  files today; see [Drop the checkout before the lint
  actions](#drop-the-checkout-before-the-lint-actions).
- A Node lane on a pull request now tests GitHub's merge commit, as the Go lanes do, instead of the
  branch tip. A job that must test the head passes it, as `test-playwright` and `lint-translations`
  do.
- `build-actions/docker` no longer accepts `version`, `secret_envs` or `secret_files`. No repository
  in either organization passes them.

## Call `gates-run.yaml` from `gates.yaml`

`gates.yaml` keeps its triggers and calls the engine. The relay and every gate step move into the
engine:

```yaml
permissions: {}

jobs:
  evaluate:
    permissions:
      contents: read
      pull-requests: read
      issues: read
    uses: a-novel-kit/workflows/.github/workflows/gates-run.yaml@<tag>
    with:
      client_id: ${{ vars.AGENT_BOT_CLIENT_ID }}
      dependabot_security_login: ${{ vars.DEPENDABOT_SECURITY_LOGIN }}
    secrets:
      app_private_key: ${{ secrets.AGENT_BOT_PRIVATE_KEY }}
```

The engine reads the org's `AGENT_KILL_SWITCH` itself. The `notify-review` job stays as it is. The
checks keep their names, since the [Agent] App posts them, so no required check changes.

## Call `dependabot-run.yaml` from the `dependabot` job

The `dependabot` job of `auto-approve-dependabot.yaml` runs its resolve, gate and approve steps
through `dependabot-run.yaml`, which takes the job's conditions and reads the halt itself. The
`auto-approve` job stays as it is:

```yaml
dependabot:
  if: github.event_name == 'workflow_run'
  permissions:
    contents: read
    pull-requests: read
    issues: read
  uses: a-novel-kit/workflows/.github/workflows/dependabot-run.yaml@<tag>
  with:
    client_id: ${{ vars.AGENT_BOT_CLIENT_ID }}
    dependabot_security_login: ${{ vars.DEPENDABOT_SECURITY_LOGIN }}
  secrets:
    app_private_key: ${{ secrets.AGENT_BOT_PRIVATE_KEY }}
```

In strict mode `auto-approve-dependabot-run.yaml` reads the pull request's live labels and holds one
labeled `breaking-release`, so a-novel/infra may drop its own hold.

## Drop the board id and the privileged labels

The board actions (`archive-board-items`, `board-write`, `derive-status`, `epic-rollback`,
`escalate`, `rollup-board`) and the reusable workflows that take `project_id` default it to the
calling org's Tasks board. Delete every `project_id: ${{ github.repository_owner == 'a-novel' && ...
}}` line.

`review-gate` reads the fleet's privileged labels from `generic-actions/privileged-labels.txt` when
`privileged_labels` is empty. Delete the list from every caller.

## Revoke head-bound labels with `revoke-labels`

`generic-actions/revoke-labels` removes every privileged label a pull request carried when a push
landed. It replaces `check-dependencies.yaml`'s `revoke-feature-env` job:

```yaml
revoke-labels:
  if: github.event.action == 'synchronize' && github.event.pull_request.labels[0] != null
  runs-on: ubuntu-latest
  permissions:
    pull-requests: write
  steps:
    - uses: a-novel-kit/workflows/generic-actions/revoke-labels@<tag>
```

| `.github/workflows/reconcile-board.yaml` | `.github/workflows/reconcile-board-run.yaml` |

Every input keeps its name. The old paths run their successors until the next major.

## Call `bot-comment-run.yaml` from the bot-comment dispatchers

The dispatcher engine moves into `bot-comment-run.yaml`. Each org's `bot-comment.yaml` keeps its
dispatch inputs, its `run-name` (the CLI finds its run by it) and its concurrency, and calls the
engine with `client_id: ${{ vars.AGENT_BOT_CLIENT_ID }}`, the six inputs and `app_private_key: ${{
secrets.AGENT_BOT_PRIVATE_KEY }}`.

## Drop `repository_config` from `renovate.yaml`

The renovate action no longer extends the base preset globally: each repository's `renovate.json`,
which extends its class preset, is its only policy. The input is ignored with a warning. Delete it.

## Drop the checkout before the lint actions

`scan-secrets`, `lint-workflows`, `lint-semgrep`, `lint-shell` and `lint-dockerfile` check the
repository out themselves, as `lint-go` does. A job that only runs one of them drops its checkout:

```yaml
# Before
steps:
  - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
    with:
      persist-credentials: false
  - uses: a-novel-kit/workflows/security-actions/scan-secrets@<tag>

# After
steps:
  - uses: a-novel-kit/workflows/security-actions/scan-secrets@<tag>
```

A job whose other steps read the repository keeps its checkout. The action checks out the same
commit again, which also removes untracked files, so an earlier step's output in the workspace is
gone; the tools the actions install live outside it.

## Let the actions pin the scanners

`version` and `sha256` are optional on the five lint actions. Each action runs the release it pins,
and Renovate moves that pin in this repository, so a scanner release reaches every repository in one
workflows update instead of one pull request per repository. Drop the pins:

```yaml
# Before
- uses: a-novel-kit/workflows/generic-actions/lint-shell@<tag>
  with:
    # renovate: datasource=custom.shellcheck depName=koalaman/shellcheck
    version: "0.11.0"
    sha256: "8c3be12b05d5c177a04c29e3c78ce89ac86f1595681cab149b65b97c4e227198"

# After
- uses: a-novel-kit/workflows/generic-actions/lint-shell@<tag>
```

A repository that must hold another release keeps passing `version`, with its annotation. For
`lint-shell` and `lint-dockerfile` it passes `sha256` with it: one without the other fails the step,
so a pinned hash never vouches for a different release.

## Keep a repository's gitleaks entries in `extra_config`

`scan-secrets` takes `extra_config`, a file holding only the repository's own `[[allowlists]]`
tables, and appends it to the shipped baseline. A `.gitleaks.toml` that restates the baseline keeps
only its own tables and moves from `config` to `extra_config`; one that adds nothing is deleted with
its `config` line.

```yaml
# Before
- uses: a-novel-kit/workflows/security-actions/scan-secrets@<tag>
  with:
    config: .gitleaks.toml

# After, with only the repository's own [[allowlists]] tables left in the file
- uses: a-novel-kit/workflows/security-actions/scan-secrets@<tag>
  with:
    extra_config: .gitleaks.toml
```

`config` still replaces the baseline whole.

## Check reproducibility with `check-reproducible`

`build-actions/check-reproducible` runs the two-builder digest comparison the services copy into
`test-reproducible-database`. It checks out by itself and defaults `file` to
`builds/database.Dockerfile`. Keep the job ID, so the required check stays the same:

```yaml
test-reproducible-database:
  runs-on: ubuntu-latest
  permissions:
    contents: read
  steps:
    - uses: a-novel-kit/workflows/build-actions/check-reproducible@<tag>
```

## Start CI services with `compose-up`

`build-actions/compose-up` holds the registry login, the `docker compose up --wait` and the log dump
on a failure that each service's `.github/actions/start-ci-services` repeats. The local action keeps
its inputs and image defaults, and hands the images to Compose through the step's `env`:

```yaml
runs:
  using: composite
  steps:
    - uses: a-novel-kit/workflows/build-actions/compose-up@<tag>
      env:
        DATABASE_IMAGE: ${{ inputs.database_image }}
        POSTGRES_PASSWORD: postgres
      with:
        services: ${{ inputs.services }}
        registry_login: ${{ inputs.registry_login }}
```

`file` defaults to `builds/compose.ci.yaml`. The job checks the repository out before the action.

## Deploy Pages with `deploy` and `publish-api-docs`

`github-pages-actions/deploy` runs configure-pages, upload-pages-artifact and deploy-pages for a
built site. `github-pages-actions/publish-api-docs` checks out a service, assembles `openapi.html`,
`openapi.yaml` when present and, given `grpc_title`, the gRPC document converted through
`buf.gen.docs.yaml`, then deploys it. A service's `publish-docs` job keeps its `if`, `needs`,
`concurrency` and `permissions`, and its steps become one:

```yaml
steps:
  - uses: a-novel-kit/workflows/github-pages-actions/publish-api-docs@<tag>
    with:
      grpc_title: JSON Keys gRPC API # omit for a REST-only service
```

`publish-storybook` deploys through `deploy`, and its callers change nothing.

## Node lanes test the merge commit

`node-actions/setup-node`'s `ref` defaults to the event's commit instead of `github.head_ref`. On a
pull request, that is GitHub's merge commit, so the Node lanes, `lint-node`, `test-node` and
`build-node` included, test the tree the Go lanes and the image builds test, and a push during the
run no longer moves what a check reports on. A job that must test the head passes it:

```yaml
- uses: a-novel-kit/workflows/node-actions/setup-node@<tag>
  with:
    github_token: ${{ secrets.GITHUB_TOKEN }}
    ref: ${{ github.event.pull_request.head.sha }}
```

## `docker` drops `version`, `secret_envs` and `secret_files`

Releases tag their images from the git tag, so the dispatched-release `version` input has no caller,
and neither do `secret_envs` and `secret_files`. A step that still passes one gets an
unexpected-input warning and loses the input's effect: pass build secrets through `secrets`.

## Keep an image's smoke flags in `run_args_file`

`build-actions/docker` takes `run_args_file`, a file holding the smoke run's flags in the syntax of
`run_args`: quoted values and `$NAME` references, no command substitution. Keep one file per image
under `builds/`, such as `builds/migrations.run-args` below, and pass it from every workflow that
builds the image, so `main.yaml` and `release.yaml` start it alike. Setting both inputs fails. A
line starting with `#` holds the reason for a flag; a reason after a flag on the same line fails the
check.

Pass the file even where a job skips the smoke run, as `main.yaml` does for a standalone image:
every build checks the file before it builds, so the pull request run of `main.yaml` catches a
broken file before a release needs it.

```text
# The migrations job reads the discrete connection settings.
-e POSTGRES_HOST="${POSTGRES_HOST}"
-e POSTGRES_PORT="${POSTGRES_PORT}"
```

```yaml
- uses: a-novel-kit/workflows/build-actions/docker@<tag>
  with:
    mode: job
    file: builds/migrations.Dockerfile
    image_name: ${{ github.repository }}/jobs/migrations
    run_args_file: builds/migrations.run-args
    github_token: ${{ secrets.GITHUB_TOKEN }}
```

## Notes

- `merge-gate-run.yaml`, which no repository called, is removed. `gates-run.yaml` replaces it.
- The `go-tools` preset matches `golangci-lint.mod`, `gotestsum.mod`, `govulncheck.mod` and `go.mod`
  in any directory and runs their post-upgrade commands in the modfile's directory. A repository
  that copied those rules for a module in a subdirectory, such as the stack's `cli/`, deletes its
  copies; its `allowed_commands` must then allow the preset's commands as they run in that
  directory.
- `verify-release-proof` also accepts an attestation from the producer's `main.yaml` at the release
  tag, for repositories whose `main.yaml` builds the release images.
- `classify-bot-change` also recognizes release pins in
  `environments/production/cluster/releases/<service>.tfvars`.
- `go-actions/test-go`'s `skip_setup` still skips the checkout, setup-go and the go-test cache. A
  job that runs no Go before `test-go`, such as a service's `test-pkg`, drops it to get the cache.
