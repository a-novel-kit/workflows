# Upgrading to v1.72.0

A checksum published beside a release no longer vouches for any tool the actions install. Whoever can
replace a release's files can replace its `checksums.txt` too, as the 2026 OVHcloud CLI compromise
did.

`security-actions/scan-secrets` and `generic-actions/refresh-apko-locks` build gitleaks and apko with
the runner's Go, which checks the source against Go's checksum database. `generic-actions/lint-shell`
and `generic-actions/lint-dockerfile` take a `sha256` input and fail on a download that does not match
it. Without one they install the release unverified and warn, and a later release requires it.

## Do I need to act?

**Not for gitleaks and apko**: their `version` pins keep working. **Recommended** now for `lint-shell`
and `lint-dockerfile`: pin each tool's SHA-256 before the release that requires it. **Only if a
`lint-semgrep` job still passes `ruleset: none`**: delete that job, as
[below](#lint-semgrep-drops-the-none-ruleset) describes. No fleet repository does.

## Pin the SHA-256

Point the annotation at the release-file datasource and add the hash on the line after `version`,
where Renovate reads it:

```yaml
# Before
- uses: a-novel-kit/workflows/generic-actions/lint-dockerfile@v1.71.0
  with:
    # renovate: datasource=github-releases depName=hadolint/hadolint
    version: "2.15.1"

# After
- uses: a-novel-kit/workflows/generic-actions/lint-dockerfile@v1.72.0
  with:
    # renovate: datasource=custom.hadolint depName=hadolint/hadolint
    version: "2.15.1"
    sha256: "c7187db94eeeeca956519a6af171adc31453941a1e777961f6e680f697c8c507"
```

`lint-shell` takes `datasource=custom.shellcheck depName=koalaman/shellcheck`, and shellcheck 0.11.0
pins `8c3be12b05d5c177a04c29e3c78ce89ac86f1595681cab149b65b97c4e227198`. For another version, GitHub
reports the digest of the file each action downloads:

```bash
gh api repos/hadolint/hadolint/releases/tags/v2.15.1 --jq '.assets[] | select(.name == "hadolint-linux-x86_64") | .digest | ltrimstr("sha256:")'
gh api repos/koalaman/shellcheck/releases/tags/v0.11.0 --jq '.assets[] | select(.name | endswith(".linux.x86_64.tar.xz")) | .digest | ltrimstr("sha256:")'
```

Make the change with the bump to v1.72.0 or after it. The two datasources ship in the v1.72.0 Renovate
presets, and an older preset reports them as unknown.

## `lint-semgrep` drops the `none` ruleset

`security-actions/lint-semgrep` no longer accepts `ruleset: none`, which ran the job without scanning. A
repository that no ruleset fits runs no `lint-semgrep` job. Delete the job, then run `a-novel repo update`
from an up-to-date default branch, so the rulesets stop requiring the check. Only the services still run
it, with `ruleset: service`. A job left on `none` fails with `unknown ruleset 'none'` once it moves to
v1.72.0.
