# Upgrading to v1.32.0

Platform browser jobs can use the shared Playwright pipeline.

## Do I need to act?

Recommended for platforms with browser component tests and Playwright journeys. Existing actions
remain compatible.

## Replace the browser steps with one action

Keep the existing job ID, permissions, timeout and coverage output. Replace Node setup, Chromium
installation, test commands, artifact uploads and Compose cleanup with:

```yaml
test-browser:
  runs-on: ubuntu-latest
  timeout-minutes: 20
  permissions:
    contents: read
    packages: read
  env:
    COMPOSE_PROJECT_NAME: browser-${{ github.run_id }}-${{ github.run_attempt }}
  outputs:
    artifact-id: ${{ steps.test.outputs.artifact-id }}
  steps:
    - uses: a-novel-kit/workflows/node-actions/test-playwright@v1.32.0
      id: test
      with:
        github_token: ${{ secrets.GITHUB_TOKEN }}
        app_private_key: ${{ secrets.DEPENDENCY_BOT_PRIVATE_KEY }}
        client_id: ${{ vars.DEPENDENCY_BOT_CLIENT_ID }}
        compose_file: builds/compose.e2e.yaml
```

The action runs `test:browser`, uploads `coverage/browser/lcov.info` as `browsercover`, then runs
`test:e2e`. Override the script or artifact inputs when the package uses different names.
Playwright configuration, fixtures and service startup stay in the consuming repository.

Omit `compose_file` when the suite needs no Compose services. When supplied, it must describe
disposable test data: cleanup removes volumes. The test runner should write service logs to
`integration-services.log` before its own teardown; the action collects them if that file is missing.

Update every workflows reference in the repository to the released tag. Verify that the existing
browser check passes, Codecov receives the coverage artifact and the `playwright-report` artifact
contains the HTML report and diagnostics. Screenshots and traces are retained for seven days.
