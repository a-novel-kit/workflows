# Upgrading to v1.69.0

`go-actions/test-go` selects packages with `include` and `exclude`, extended regular expressions over
package import paths. They reach the script as data. The shell-pipeline inputs `filter_patterns` and
`filter_extra_patterns` are deprecated, and a later release removes them.

## Do I need to act?

**Not yet.** A caller that sets neither pipeline, or only `filter_extra_patterns`, tests the same
packages as before. **Recommended** now: move each pipeline to the patterns before the removal.

## Replace the pipelines

`exclude` defaults to `/mocks|/test|/proto`, the paths the old default pipeline dropped. A `grep`
pipeline becomes `include`, and a `grep -v` pipeline joins `exclude`:

```yaml
# Before
- uses: a-novel-kit/workflows/go-actions/test-go@v1.68.0
  with:
    filter_extra_patterns: "| grep /internal | grep -v /protogen"

# After
- uses: a-novel-kit/workflows/go-actions/test-go@v1.69.0
  with:
    include: /internal
```

`/protogen` needs no pattern of its own, because the default `exclude` already matches it through
`/proto`. A caller that overrode `filter_patterns` to keep one of the default paths, such as `/test`,
sets `exclude: /mocks|/proto` instead. Join alternatives with `|`; an empty `exclude` skips nothing.
