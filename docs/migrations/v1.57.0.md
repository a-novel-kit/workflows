# Upgrading to v1.57.0

`v1.57.0` lets a release run with one approval, as the release App, and lets a hotfix publish like
a release (a-novel/.github#414). Each releasing repository's `release.yaml` splits in three:

- **`plan`** rehearses the cut with no environment and no credential. `release-core` mints no token on
  a dry run and checks out with the job's own token.
- **`cut`** runs in the protected `release` environment, whose `RELEASE_BOT_PRIVATE_KEY` secret only
  an approved job reads, and pushes the version commit, the tags and the GitHub Release as the
  release App. `release-core` refuses a cut without that key.
- **The tag publishes.** The tag the cut pushes runs `release.yaml` again, and that run builds the
  images and attestations, publishes the packages and asks infra to deploy, all with
  `GITHUB_TOKEN`. Only the release App and admins can create a tag, so one approval covers the
  release. A hotfix cut's tag runs the same jobs from its release line's files.

The release train waits up to an hour for each cut's approval and links the run in its summary. A
rehearsal waiting at the `release` environment parks its repository at once, since only a
`release.yaml` that predates the split rehearses there. The managed `hotfix.yaml` passes the release App's credentials to
`release-line-run` once its template moves to this release; until then the hotfix cut keeps the
agent's.

## Do I need to act?

**Every repository with a `release.yaml` adopts the split.** An admin still releases the same way,
from Actions ▸ release, or through the release train. The environment asks for an approval once
a-novel-kit/stack#609 gives it reviewers; the admin who dispatched may approve their own run.

1. Add the tag trigger, and name the run after either event:

   ```yaml
   on:
     workflow_dispatch: # unchanged
     workflow_call: # unchanged
     push:
       tags: ["v*"]

   run-name: "${{ github.event_name == 'push' && format('📦 publish {0}', github.ref_name) || format('🚀 release {0}{1}', inputs.release_type, inputs.dry_run && ' (dry-run)' || '') }}"
   ```

2. Replace the `release` job with `plan` and `cut`:

   ```yaml
   plan:
     if: github.event_name != 'push'
     runs-on: ubuntu-latest
     permissions:
       contents: read
     steps:
       - uses: a-novel-kit/workflows/publish-actions/release-core@v1.57.0
         with:
           # renovate: datasource=go depName=github.com/a-novel-kit/stack/cli
           cli_version: "1.7.5"
           release_type: ${{ inputs.release_type }}
           dry_run: "true"

   cut:
     needs: plan
     if: github.event_name != 'push' && !inputs.dry_run
     runs-on: ubuntu-latest
     environment: release
     permissions:
       contents: read
     steps:
       - uses: a-novel-kit/workflows/publish-actions/release-core@v1.57.0
         with:
           # renovate: datasource=go depName=github.com/a-novel-kit/stack/cli
           cli_version: "1.7.5"
           release_type: ${{ inputs.release_type }}
           client_id: ${{ vars.RELEASE_BOT_CLIENT_ID }}
           app_private_key: ${{ secrets.RELEASE_BOT_PRIVATE_KEY }}
   ```

   A repository that only tags, such as a Go library, keeps its board archive as a step after the
   cut and needs no tag-triggered job.

3. Run every publishing job on the tag instead of after the release job. Each one drops
   `needs: [release]` and `if: ${{ !inputs.dry_run }}` for `if: github.event_name == 'push'`, and
   reads the tag from `github.ref_name`:

   ```diff
    build-grpc:
   -  needs: [release, build-database]
   -  if: ${{ !inputs.dry_run }}
   +  needs: [build-database]
   +  if: github.event_name == 'push'
      ...
          - uses: a-novel-kit/workflows/build-actions/docker@v1.57.0
            with:
              file: builds/grpc.Dockerfile
              image_name: ${{ github.repository }}/grpc
   -          version: ${{ needs.release.outputs.version }}
   ```

   `build-actions/docker` derives the `vX.Y.Z`, `vX.Y` and `vX` tags from the tag ref when no
   `version` is passed. An image read at the release's tag, such as the database a server build
   starts, is `:${{ github.ref_name }}`. `publish-actions/npm` publishes the checked-out tag when
   `ref` is empty, and `publish-actions/deploy-release` takes `version: ${{ github.ref_name }}`.
   The deploy dispatch and the board archive keep the agent's credentials: infra verifies what it
   pins, so the dispatch only asks.

## Limits

- A release line cut before its repository adopts the split carries the old `release.yaml`, which
  has no tag trigger, so a hotfix on that line tags without publishing. Lines cut after adoption
  publish their hotfixes.
- GitHub creates no push event for more than three tags in one push, and `release-core` pushes the
  root tag with every sub-module tag. A repository with three or more Go sub-modules would release
  without publishing; none has more than one today.
