# Upgrading to v1.44.0

`v1.44.0` stops `generic-actions/approve-playwright` from holding a runner while main CI runs. The
approval job used to wait for the head's main run on every PR push, then copy its drift review. It
now records the approval receipt and finishes in seconds.

## Do I need to act?

**Only in platforms that call `approve-playwright`.** Without the change below, a screenshot label
added or removed while main is still running takes effect only on the next push.

## Run the approval job when main completes

A label change that lands mid-run is now applied when main completes, through the `workflow_run`
trigger the visual workflow already declares. Let the approval job run on it for branch pushes, and
shorten its timeout:

```yaml
approval:
  if: >-
    ${{ vars.VISUAL_CI_PROVIDER != '' && (github.event_name == 'pull_request_target' ||
    (github.event.workflow_run.event == 'push' &&
    github.event.workflow_run.head_branch != github.event.repository.default_branch)) }}
  runs-on: ubuntu-24.04
  timeout-minutes: 5
  concurrency:
    # A completion event names no PR, so each one gets its own group.
    group: visual-approval-${{ github.event.pull_request.number || github.run_id }}
    cancel-in-progress: false
  permissions:
    contents: read
    actions: write
    statuses: write
    pull-requests: read
  steps:
    - uses: a-novel-kit/workflows/generic-actions/approve-playwright@v1.44.0
      with:
        github_token: ${{ secrets.GITHUB_TOKEN }}
```

The permissions are unchanged.

## What reviewers see

- The approval run no longer carries a copy of `playwright-drift.html`. Open the failing
  `visual-comparison` check instead: it targets main's run, whose summary links the Old / New / Diff
  review.
- A label change reruns only `test-browser` and the jobs that need it, not the whole main run.
