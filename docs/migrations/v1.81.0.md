# Upgrading to v1.81.0

`go-actions/lint-go` no longer accepts `working-directory`, `build-actions/docker` no longer accepts
`secret-envs` or `secret-files`, and `build-actions/docker-job` is removed. [v1.78.0](./v1.78.0.md)
deprecated them for `working_directory`, `secret_envs`, `secret_files`, and `docker` with `mode: job`.

## Do I need to act?

**Yes**, if a step still uses an old name. Every repository in both organizations has already moved, so a
repository whose runs on v1.80 log no deprecation warning needs nothing beyond the pin move. Otherwise,
make the [v1.78.0](./v1.78.0.md) changes in the same change that moves the pin to `v1.81.0`. To list the
steps to check:

```bash
grep -rn -A12 -E 'build-actions/docker(-job)?@|go-actions/lint-go@' .github/workflows
```

A stale name does not always fail the job:

- **`working-directory` on `lint-go`.** GitHub warns of an unexpected input and ignores it, so the step
  lints and scans the repository root instead of the module.
- **`secret-envs` or `secret-files` on `docker`.** GitHub ignores them the same way, so the build runs
  without those secrets.
- **`build-actions/docker-job`.** The job fails before its first step, since the action no longer exists
  at this tag.

## Notes

Earlier tags keep the old names and `docker-job`, so a release line that pins one needs nothing.
