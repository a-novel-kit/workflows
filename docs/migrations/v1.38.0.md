# Upgrading to v1.38.0

`v1.38.0` moves protobuf regeneration out of the base Renovate preset into an opt-in `protobuf`
preset. Every class used to run `go tool -modfile=buf.mod buf generate` on a
`google.golang.org/protobuf` update, which fails in repositories without `buf.mod` or without that
command in their allowlist.

## Do I need to act?

**Only in repositories that generate protobuf code with `buf.mod`**: `service-json-keys`,
`service-genai`, `service-template` and `golib`. Without the preset they stop regenerating on a
protobuf update, and `generated-go` reports the stale output instead. Every other repository needs
nothing; the update now passes without a post-upgrade task.

## Add the protobuf preset

Extend it beside the class preset, on the same release:

```json
{
  "extends": [
    "github>a-novel-kit/workflows//renovate/service#v1.38.0",
    "github>a-novel-kit/workflows//renovate/protobuf#v1.38.0"
  ]
}
```

The workflows update group moves both references together from then on. Keep
`go tool -modfile=buf.mod buf generate` permitted by the repository's `allowed_commands`.
