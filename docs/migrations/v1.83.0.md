# Upgrading to v1.83.0

Each repository keeps its Discord channel webhooks as its own secrets, `REVIEWS_WEBHOOK` and
`ISSUES_WEBHOOK`, so changing one channel sets one secret. A repository secret wins over the org's
of the same name, so a repository without its own channel posts to the org's. The issues feed and
the stuck-pull-request feed run in each org's `.github` repository, which cannot read those secrets:
they now hand each repository its posts through the new `discord-dispatch` action, which dispatches
that repository's `notify-post.yaml`.

- **`discord-post` drops `webhooks` and `repository`.** It posts to `webhook` alone.
- **`notify-pr-run` drops the `reviews_webhooks` secret.** `reviews_webhook` is the repository's own
  channel, which its caller passes as `REVIEWS_WEBHOOK`.
- **`notify-issues-run` dispatches instead of posting.** It drops the `roles` and `bws_server_url`
  inputs and the `webhook`, `webhooks` and `bws_access_token` secrets.
- **`notify-stuck-run` dispatches its review posts.** It drops the `bws_server_url` input and the
  `reviews_webhook`, `reviews_webhooks` and `bws_access_token` secrets. Its dependencies posts stay as
  they were.

## Do I need to act?

**Every repository with its own channels sets them as repository secrets** before its callers stop
passing the maps, or its posts move to the org's channels. Each command prompts for the webhook:

```bash
gh secret set REVIEWS_WEBHOOK --repo <org>/<repo>
gh secret set ISSUES_WEBHOOK --repo <org>/<repo>
```

The org's issues channel becomes an org secret too, for the repositories without their own:

```bash
gh secret set ISSUES_WEBHOOK --org <org> --visibility all
```

**Every repository carries `notify-post.yaml`** before its org's `.github` moves to `v1.83.0`: the
dispatch to a repository without it fails with a warning, and that repository's posts are lost.
Copy [this repository's own](../../.github/workflows/notify-post.yaml), the `.github` repositories
included, whose issues post through it too.

**Every caller stops passing what the engines dropped** before moving to `v1.83.0`: a workflow that
passes an input or a secret the reusable workflow does not declare fails to start. In `notify.yaml`
and `gates.yaml`:

```diff
       reviews_webhook: ${{ secrets.REVIEWS_WEBHOOK }}
-      reviews_webhooks: ${{ secrets.REVIEWS_WEBHOOKS }}
```

In each `.github` repository's `notify-issues.yaml`:

```diff
       client_id: ${{ vars.AGENT_BOT_CLIENT_ID }}
-      roles: ${{ vars.DISCORD_REPO_ROLES }}
-      bws_server_url: ${{ vars.BWS_SERVER_URL }}
     secrets:
       private_key: ${{ secrets.AGENT_BOT_PRIVATE_KEY }}
-      webhook: ${{ secrets.ISSUES_WEBHOOK }}
-      webhooks: ${{ secrets.ISSUES_WEBHOOKS }}
-      bws_access_token: ${{ secrets.BWS_READ_TOKEN }}
```

And in its `notify-stuck.yaml`:

```diff
       roles: ${{ vars.DISCORD_REPO_ROLES }}
-      bws_server_url: ${{ vars.BWS_SERVER_URL }}
     secrets:
       private_key: ${{ secrets.AGENT_BOT_PRIVATE_KEY }}
       dependencies_webhook: ${{ secrets.DEPENDENCIES_WEBHOOK }}
-      reviews_webhook: ${{ secrets.REVIEWS_WEBHOOK }}
-      reviews_webhooks: ${{ secrets.REVIEWS_WEBHOOKS }}
-      bws_access_token: ${{ secrets.BWS_READ_TOKEN }}
```

Once both `.github` repositories run `v1.83.0`, the `REVIEWS_WEBHOOKS` org secret and the `.github`
repository's `ISSUES_WEBHOOKS` secret are unused: delete them.
