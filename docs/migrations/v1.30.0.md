# Upgrading to v1.30.0

`v1.30.0` makes verifiable provenance part of every successful `build-actions/docker` and
`build-actions/docker-job` publication. After the final GHCR push, the action signs the exact output
digest through GitHub's OIDC-backed attestation service and publishes the attestation beside the
image.

## Do I need to act?

Only if a job calls either Docker build action without the complete permission set below. The known
A-Novel service and platform callers already grant it.

```yaml
permissions:
  attestations: write
  contents: read
  id-token: write
  packages: write
```

No long-lived signing key or new secret is required. GitHub exchanges the job's short-lived OIDC
identity for a Sigstore signing certificate. The action deliberately disables the optional linked
artifact storage record, so `artifact-metadata: write` is not needed.

## Failure behavior

The job fails if the image push succeeds but GitHub cannot sign, upload, or attach the attestation.
Treat that workflow release as incomplete even though a registry object may exist. Fix the caller's
permissions or the attestation failure, then publish a fresh SemVer release; never move or backfill
the failed release tag.

## Verify a release image

Use the immutable image digest and the repository that built it:

```bash
gh attestation verify \
  oci://ghcr.io/a-novel/service-json-keys/grpc@sha256:<64-hex-digest> \
  --repo a-novel/service-json-keys
```

Verification must succeed for the expected repository and fail for a different repository or
digest. Consumers need only public read access; they do not need `packages: write`, OIDC, or an
attestation-writing permission.
