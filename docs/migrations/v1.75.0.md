# Upgrading to v1.75.0

`generic-actions/lint-shell`, `generic-actions/lint-dockerfile`, `security-actions/lint-semgrep` and
`security-actions/lint-workflows` now require their pins. v1.72.0 and v1.74.0 introduced them and only
warned without one; the warning left a path where a replaced release file or a moved image tag ran
unverified.

- `lint-shell` and `lint-dockerfile` fail when `sha256` is empty.
- `lint-semgrep` and `lint-workflows` fail when `version` carries no `@sha256:` digest.

## Do I need to act?

**Only if a job still runs one of these actions without its pin.** Every repository in both
organizations pins them already. Check a repository with:

```bash
grep -rn -A6 -E 'lint-(shell|dockerfile|semgrep|workflows)@' .github
```

## Add a missing pin

- For `lint-shell` and `lint-dockerfile`, follow [Upgrading to v1.72.0](v1.72.0.md): add `sha256` on
  the line after `version` and switch the annotation to the `custom.shellcheck` or `custom.hadolint`
  datasource.
- For `lint-semgrep` and `lint-workflows`, follow [Upgrading to v1.74.0](v1.74.0.md): write the image
  digest after the tag in `version`.
